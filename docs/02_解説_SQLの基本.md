# 解説：SQL の基本（演習1・演習2の背景）

## SELECT 文が実行される順序

書く順序と、データベースが処理する順序は違います。処理順序を理解すると、エラーの理由や集計の動きが見えるようになります。

書く順序：

```sql
SELECT 列 FROM テーブル WHERE 条件 GROUP BY 列 HAVING 条件 ORDER BY 列 LIMIT 件数
```

処理される順序（概念）：

1. **FROM**：どのテーブルから取るか
2. **WHERE**：行を絞り込む（集計の「前」に行われる）
3. **GROUP BY**：グループに分ける
4. **集計**：COUNT、SUM などをグループごとに計算する
5. **HAVING**：集計した「後」の結果を絞り込む
6. **SELECT**：出す列を決める（別名 `AS` はここで付く）
7. **ORDER BY**：並び替える
8. **LIMIT**：件数を切る

この順序から分かること：

- `WHERE` には集計結果（例：`SUM(...) >= 10000`）は書けません。集計後の絞り込みは `HAVING` の役割です
- `ORDER BY` では `SELECT` で付けた別名が使えます（処理が後だからです）

## 「大きなテーブルでも速い」理由の入口

演習2では、約150万行の `orders` テーブルや、約600万行の `lineitem` テーブルを検索します。それでもすぐ結果が返る理由の一つは、Snowflake がテーブルを内部的に小さな塊（マイクロパーティション）に分けて保存し、各塊について「最小値・最大値などのメタデータ」を持っていることです。

- `WHERE o_orderdate >= '1998-01-01'` のような条件があると、範囲外の塊は**読まずにスキップ**できます（プルーニング）
- `SELECT *` で全列を読むより、必要な列だけを選ぶ方が読むデータ量が減ります。列指向の保存方式のため、選んだ列の分だけ読まれます

つまり「速いクエリを書く」とは、突き詰めると「**読むデータ量を減らす**」ことです。WHERE で絞る、列を選ぶ、が基本になります。

## COUNT(*) が一瞬で返る理由

テーブルの行数はメタデータとして保持されているため、`SELECT COUNT(*) FROM 大きなテーブル` は全行を読まなくても答えられます。演習2の最初のクエリが速かったのはこのためです。一方、`WHERE` 条件付きの COUNT は、条件に合う塊だけを読む必要があります。
