# 確認クイズと解答（講師用／復習用）

当日はまず考えてから、このファイルで答え合わせをしてください。

## クイズ

**Q1.** ウェアハウスの課金が発生するのはどのようなときか？
**Q2.** Auto Suspend が無い LARGE ウェアハウスを48時間動かしっぱなしにすると、何クレジット消費するか？（LARGE = 8クレジット/時）
**Q3.** `WHERE` に `SUM(quantity * unit_price) >= 100000` と書くとエラーになる理由は？正しくはどう書くか？
**Q4.** 大きなテーブルへの `SELECT COUNT(*)`（条件なし）が速い理由は？
**Q5.** JSON に存在しないキーを取り出すとどうなるか？
**Q6.** CLONE と CREATE TABLE AS SELECT の違いを、作成直後のストレージの観点で説明すると？
**Q7.** Time Travel で「先月の状態」を常に見られるとは限らない理由は？

## 解答

**A1.** ウェアハウスが起動している（RUNNING な）間だけ、サイズに応じたクレジットを消費する。ストレージの課金とは別。

**A2.** 8 × 48 = **384クレジット**。無料トライアル枠（$400分）の大半を、誰も使っていない時間で失いかねない計算になる。これが Auto Suspend が必須と言われる理由。

**A3.** `WHERE` は集計より前に処理されるため、集計結果はまだ存在しないから。正しくは `GROUP BY` の後に `HAVING SUM(quantity * unit_price) >= 100000` と書く。

**A4.** テーブルの行数はメタデータとして保持されているため、全行を読まなくても答えられるから。

**A5.** エラーにはならず、その行の値は **NULL** になる。

**A6.** CLONE は作成直後、実データを複製しない（参照のみ）ためストレージがほぼ増えない。CREATE TABLE AS SELECT は全データを実コピーするため、元と同じ量のストレージが増える。

**A7.** 過去データを保持する期間（リテンション期間）がエディションや設定で決まっており、期間を過ぎた状態は参照できないため。バックアップとは別物。

## チャレンジ課題の解答例と期待値

### 演習1のチャレンジ

- 商品ごとの売上：ノートPC 240,000 ／ モニタ 70,000 ／ マウス 9,000 ／ キーボード 8,000
- 2026-11-03 の注文件数：2件、売上合計 128,000
- 売上が 100,000 以上の顧客（HAVING）：田中 190,000、鈴木 129,000

```sql
-- 商品ごとの売上
SELECT product, SUM(quantity * unit_price) AS total_amount
FROM orders GROUP BY product ORDER BY total_amount DESC;

-- 日付で絞り込む
SELECT COUNT(*) AS order_count, SUM(quantity * unit_price) AS total_amount
FROM orders WHERE ordered_at = '2026-11-03';

-- 集計後の絞り込みは HAVING
SELECT customer, SUM(quantity * unit_price) AS total_amount
FROM orders GROUP BY customer
HAVING SUM(quantity * unit_price) >= 100000
ORDER BY total_amount DESC;
```

### 演習4のチャレンジ

- action ごとの件数：login 1件、purchase 1件、logout 1件
- amount の合計：3,000（amount が無い行は NULL として集計から除かれる）

```sql
SELECT payload:action::VARCHAR AS action, COUNT(*) AS cnt
FROM events GROUP BY action ORDER BY cnt DESC;

SELECT SUM(payload:amount::NUMBER) AS total_amount FROM events;
```

### 演習5のチャレンジ

- `orders_backup` を DROP した後に `UNDROP TABLE orders_backup;` を実行すると、テーブルが復活し、件数5件が確認できる
- 考察（CLONE の使い分け）：検証・開発用途では CLONE が速くて安い。ただしコピー元が本番の個人情報を含む場合、コピー先の権限管理やマスキングが別途必要になる。「コピーが簡単」なことと「コピーしてよい」ことは分けて考える

### 演習2・演習3について

この2つは「正解の値」ではなく「観察」が目的です。実行時間は環境やキャッシュで変動するため、絶対値ではなく「サイズを上げたらどう変わったか」「条件を付けたらどう変わったか」の傾向を見てください。2回目の実行が速い場合は、結果キャッシュの影響も考えられます。
