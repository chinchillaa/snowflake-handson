# 解説：半構造化データ（演習4の背景）

## なぜ JSON をそのまま入れるのか

ログや API のレスポンス、IoT デバイスの送信データは、項目が固定されていない JSON 形式で届くことがよくあります。従来のリレーショナルデータベースでは、先に列を設計してからでないと取り込めませんでした。

Snowflake では `VARIANT` 型の列に JSON をそのまま格納できます。

- 取り込み時点では形式を決めなくてよい（あとから必要な項目だけを取り出せる）
- 項目が増えたり減ったりしても、テーブル定義を変えなくてよい
- 取り出しは SQL の中で `payload:キー` と書くだけでよい

## 取り出しの基本形

```sql
payload:user::VARCHAR
│        │    └─ ::型 で型を決める（キャスト）。集計や結合に使うなら必須
│        └────── :キー で JSON の中身を取り出す
└─────────────── VARIANT 型の列名
```

入れ子になっている JSON は `payload:address:city` のように `:` をつないでたどれます。配列は `FLATTEN` 関数で行に展開できます（発展課題）。

## 注意点

- キーが存在しない行では結果が **NULL** になります。エラーにはなりません。演習4で `amount` が NULL になった行がそれです
- 「何でも入る」便利さの反面、どんな項目が入っているかはデータを見ないと分かりません。実務では、よく使う項目だけを通常の列として切り出してテーブル化する（＝構造化する）運用と組み合わせます
- 大きな JSON を毎回丸ごと検索すると読む量が増えます。VARIANT の中でも、検索条件によく使うキーは列として持つ方が高速です
