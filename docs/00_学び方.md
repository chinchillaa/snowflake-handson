# このハンズオンの学び方

このハンズオンは「SQL を貼って実行するだけ」では終わりません。各演習は次の4ステップで進めます。

## 予測 → 実行 → 観察 → 考察

1. **予測する（実行前）**
   SQL を実行する前に「どんな結果が返ると思うか」を言葉にします。行数、並び順、金額の大小、実行時間の見当など、何でも構いません。
   予測が外れること自体が学びです。外れたら「なぜ外れたか」が一番の収穫になります。

2. **実行する**
   SQL を実行します。エラーが出たら、まずエラーメッセージを最後まで読んでください。「どのオブジェクトが無いと言われているか」「どの行か」が書かれています。

3. **観察する**
   結果のどこを見るかを、各演習の「観察ポイント」に書いてあります。特に次を意識してください。
   - 結果の行数と、代表的な値（最大・最小・合計）
   - 実行時間（結果グリッド下部や Query History で確認できます）
   - 使われたウェアハウスと、そのサイズ

4. **考察する（ワークシートに書く）**
   `docs/ワークシート.md` の各演習の欄に、予測と結果の違い、気づいたことを1〜2行で書きます。書くことで「分かったつもり」を防ぎます。

## 自分で書くチャレンジ課題について

各演習 SQL の末尾には **チャレンジ** があります。これは答えの SQL が用意されていない課題です。

- まず演習で使った SQL を「書き換える」ところから始めてください。ゼロから書く必要はありません
- 詰まったら、演習内の似たクエリを見返すのが一番のヒントです
- 期待する結果（行数や合計値）は課題文に書いてあるので、自分のクエリの答え合わせができます
- 講師用の解答例は `docs/06_クイズと解答.md` にあります。当日はまず自分で考える時間を取ってください

## つまずいたときの確認順序

SQL のトラブルの大半は、次の3つのどれかです。上から順に確認してください。

1. **コンテキスト**：画面上部（または `USE` 文）で、正しいウェアハウス／データベース／スキーマを選んでいるか
2. **オブジェクト名**：テーブル名や列名の綴りが合っているか（`SHOW TABLES;` などで実物を確認できます）
3. **実行順序**：前の演習ファイルを実行し忘れていないか（例：演習5は演習1の `orders` テーブルが前提です）
